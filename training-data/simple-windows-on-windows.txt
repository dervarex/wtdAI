With computers Windows on Windows often shortened to WOW is a compatibility layer of x versions of the Microsoft Windows NT family of operating systems that allows many legacy bit programs run that were made for Windows .x or before to run. WOW allows many bit Windows programs to run without changes on newer bit versions of Windows. This was made to give software developers time to make their software bit while people moved from Windows . x to Windows so the OS can be upgraded to a newer version while running most or all of a customer's bit programs. Windows x operating systems which were made on top of DOS had both and bit systems so if it kept those bit parts the OS could run bit software without emulation. NT based versions are very different in how they run so they need a more sophisticated solution. There are two main techniques to let bit programs run on bit versions of Windows with some limitations called thunking and shimming. WOW thunks bit instructions into bit equivalents to permit bit pointers memory spaces and address spaces. bit programs usually run in a single virtual DOS machine sharing memory between them. However they can be changed to run in a private separate memory space where every bit process has a separate process. This can reduce system crashes by not letting programs interfere with others but it can cause reduced bit inter process communication and can use more of your computer's memory. WOW is a part of bit editions of Windows NT. bit versions of Windows including Windows Server R and later where they only have bit versions can not run bit software without using different emulation software for example DOSBox . WOWEXEC.EXE on Windows NT allows WoW to work. Windows on Windows can using the WIN.COM file emulate the Windows .x for NTVDM Windows and Windows kernels which can run bit DOS powered Windows applications on Windows NT. Problems with applications running on newer operating systems especially with long filenames multiple user accounts and least privilege may prohibit some applications from working correctly. For example they might incorrectly think that they can write files to any part of the file system but NTFS file permissions exist and does not allow this in many system folders. When Microsoft was building Windows they had to ensure old programs still worked with . filenames to allow old applications to keep working properly. Since Windows there was a feature where both a long and short file name are kept so older applications could still use the . filenames. Programs that try to access hardware directly can't do so. Old programs may also not work if they expect certain system configuration files from DOS and Windows x that are not used in Windows NT operating systems so empty versions of files like AUTOEXEC.BAT and CONFIG.SYS exist even though Windows NT does not use them. Many shims exist in the application compatibility layer of later versions of Windows to capture and change API calls from old applications made with different assumptions about the operating system in mind.
